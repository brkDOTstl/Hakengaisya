# Optional DEI participation

Use all user-permitted route families as planner input; never pre-filter to the host model's family. Optional worker.model_family labels are declared metadata only. plan.routing_audit lists each supplied candidate by work item with selected, eligible-not-selected or excluded and its reason. This cannot detect a provider the host omitted or create a missing connection.

Task-first briefs may set dei:{"enabled":true,"model_ids":["MODEL_A","MODEL_B"]}. Omitted/false means ordinary adequate cost/time routing, no roster filter and no DEI score. The enabled roster must contain unique exact model IDs. All assignments must name a selected model_id and actual route. Multiple routes for one ID do not satisfy multiple models.

With workers, the planner reserves existing qualified deliverables for each selected model and then applies normal tool, hierarchy, independence, budget and capacity checks. Unresolved coverage is an unsuccessful plan; do not execute it or create busywork. The matching/scheduling heuristic does not prove global infeasibility. Without worker profiles, the host verifies actual capability before binding; costs remain unknown. Snapshot the policy at run creation. Enabled DEI does not support legacy template rehearsals.

Participation needs an owner assignment, start and submitted contracted outputs plus inspectable work evidence. A rejected submission counts; a planned call, idle assignment, start-only record, greeting or no-op does not. The host inspects actual calls and outputs; IDs/references are not authentication. The helper does not launch models or authorize additional calls. Sequential work is valid cooperation.

node HELPER agent-review RUN.json returns the root manager's local report. next/event include agent_review, terminal review supplies agent_review_preview, and accepted handover stores the final review automatically. Disabled or unfinished runs have score:null and no tag. Completed full coverage scores 10; an omission scores 1 and adds dei-non-compliant with missing model IDs. Technical completion may pass with this management penalty. Reopen clears final scoring until completion, preserving prior participation and review history.

The overall roster obligation belongs to the root manager, not each supplier's individual reviewer. Report management policy separately from technical quality and D1-D6. Do not upload task journals, infer human discrimination claims, or put this score in the independent evaluator's technical endpoint. No hosted management-review API is provided in this version.

Federation projects preserve their declared dei policy through buyer brief compilation and handoff checks. Only declared buyer-packet model bindings earn buyer-level credit. A supplier's internal model calls are not enumerated by its receipt; use its local run for those observations. No live client connection is established by this policy.
